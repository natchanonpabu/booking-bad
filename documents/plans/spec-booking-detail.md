# สเปกหน้า "รายละเอียดการจอง" (D62)

สถานะ: ร่างสำหรับตัดสินและลงมือทำ · ผู้ตัดสิน: ผู้ก่อตั้ง · อัปเดต 2026-10-29

หน้านี้ถูกเรียกว่า "จุดขาดที่ยากที่สุดในทั้งชุด" (ia.md) ปุ่มยกเลิก ใบเสร็จ และจองซ้ำ ตอนนี้ไม่มีหน้ารองรับ การ์ดในหน้า "การจองของฉัน" ยังกดเข้าไปไหนไม่ได้ และยกเลิกด้วย Modal ในรายการโดยไม่มีกติกาเรื่องเวลา

อ้างอิง: [DESIGN.md](../../apps/liff/DESIGN.md) (สี/ตัวอักษร/เลย์เอาต์), [types.ts](../../apps/liff/src/data/types.ts) (`Booking`, `BookingStatus`, `PaymentStatus`), [register.md](../audit/register.md) (D16, D22, D62, D74)

## 3. ข้อมูลที่ใช้

มีอยู่แล้วใน `Booking`: `ref, courtIds, date, startMinutes, endMinutes, status, lines, total, paymentMethod, paymentStatus, paidAt, contactPhone, headcountHint, createdAt`

ต้องเพิ่มเพื่อให้หน้านี้ทำงาน:

| ข้อมูล | ใช้ทำอะไร |
|---|---|
| `Venue.cancellationHours` เปลี่ยนค่าจาก 3 เป็น **24** | คำนวณสิทธิ์เครดิต (เป็นข้อมูลต่อสนาม ไม่ฝังในโค้ด) |
| `Venue.creditExpiryDays = 30` (ใหม่) | วันหมดอายุเครดิต |
| `Booking.cancelledAt: number \| null` | แสดงเวลายกเลิก |
| `Booking.creditIssued: Satang` (0 ถ้าไม่ได้) และ `Booking.creditPending: boolean` | แสดงเครดิตที่ได้ หรือ "รอคนจองต่อ" สำหรับการยกเลิกที่ <24 ชม. |
| ตารางเครดิตใหม่ `CreditEntry { id, userId, venueId, amount: Satang, issuedAt, expiresAt, sourceBookingId, usedOnBookingId \| null }` | ยอดเครดิตของผู้ใช้ (ledger) ไม่เก็บเป็นตัวเลขเดียว |
| ตารางคำขอเครดิตรอ `PendingCredit { id, venueId, userId, sourceBookingId, amount, courtId, date, startMinutes, endMinutes, resolvedByBookingId \| null }` | เก็บการยกเลิก <24 ชม. ที่รอคนจองต่อ แปลงเป็น `CreditEntry` เมื่อเงื่อนไขครบ (ข้อ 6.2) |
| `User.venueId` (ผู้ใช้แยกต่อสนาม) | สมาชิกเป็นของสนามนั้น ๆ ใน DB ให้เป็น unique ต่อ `(venueId, lineUserId)` เครดิตและการจองผูกกับผู้ใช้ของสนามนั้น |
| `api.getBooking(ref)`, `api.cancelBooking(id)` คืนผลว่าได้เครดิตเท่าไร | หน้านี้ไม่คำนวณเองฝั่งไคลเอนต์ (เซิร์ฟเวอร์ตัดสิน) |

เงินใช้ `Satang` เสมอและแสดงผ่าน `lib/money.ts` เท่านั้น

## 4. สถานะที่ต้องแสดง

ตัวป้ายสถานะ (pill) มี 1 ตัวต่อการจอง ไม่แยกสถานะจอง/สถานะจ่ายออกเป็นสองป้าย (กันสับสน)

| เงื่อนไข | ป้าย | สี (token) | ข้อความย่อย |
|---|---|---|---|
| `confirmed` + `unpaid` + วันเวลายังไม่ถึง | จองแล้ว · ชำระที่เคาน์เตอร์ | `secondary-container` | "ชำระ ฿220 ที่เคาน์เตอร์ก่อนเล่น" |
| `confirmed` + `paid` | ชำระแล้ว | `success` / `success-container` | แสดงเวลา `paidAt` |
| `pending_payment` | รอชำระ | `secondary-container` | นับถอยหลังถึง `holdExpiresAt` (จะเกิดเมื่อมีการจ่ายล่วงหน้า) |
| `completed` | เล่นเสร็จแล้ว | `muted` | — |
| `cancelled` | ยกเลิกแล้ว | `error-container` | เวลายกเลิก + เครดิตที่ได้ หรือ "รอคนจองต่อเพื่อรับเครดิต" หรือ "ไม่มีเครดิต" |
| `expired` | หมดเวลาถือคอร์ท | `muted` | "คอร์ทถูกปล่อยกลับแล้ว" |

ห้ามแยกสถานะด้วยสีอย่างเดียว ต้องมีข้อความกำกับเสมอ (กฎ DESIGN.md ข้อ 2.4)

## 6. ปุ่มและกติกา

### 6.1 ปุ่มที่แสดงตามสถานะ

| สถานะ | ปุ่มหลัก | ปุ่มรอง |
|---|---|---|
| ยังไม่ถึงเวลา (`confirmed`/`pending_payment`) | **ยกเลิกการจอง** (outline, ไม่ใช่ปุ่มสีแดงเต็ม) | จองซ้ำ (เลือกวันเวลาใหม่) |
| `completed` | **จองซ้ำเหมือนเดิม** (คอร์ท/เวลาเดิม วันถัดไปที่ว่าง) | — |
| `cancelled` / `expired` | **จองใหม่** | — |

"จองซ้ำ" พาไป `/book` พร้อมคอร์ทและช่วงเวลาเดิมเป็นค่าเริ่มต้น ถ้าช่วงนั้นไม่ว่างให้พาไปตารางโดยไม่เลือกช่อง

### 6.2 กติกายกเลิกและเครดิต

ให้เซิร์ฟเวอร์คำนวณ หน้าแค่แสดงผล:

| กรณี | ยกเลิกได้ไหม | ได้เครดิตไหม |
|---|---|---|
| ก่อนเริ่ม ≥ 24 ชม. และ **ชำระแล้ว** | ได้ | ได้ทันที = ยอดที่ชำระ (บาท) หมดอายุ 30 วันนับจากวันออก |
| ก่อนเริ่ม < 24 ชม. และ **ชำระแล้ว** | ได้ | **รอ** ออกเมื่อมีคนจองช่วงเวลานั้นต่อและชำระแล้ว ถ้าเลยเวลาเริ่มโดยไม่มี = ไม่ได้ |
| **ยังไม่ชำระ** (ทุกกรณี) | ได้ | ไม่มี |
| เริ่มไปแล้ว | ไม่ได้ | — |
| สนามเป็นฝ่ายยกเลิก | — | ได้เต็มจำนวนทันที |
| no-show | — | ไม่ได้ |

**กติกาเครดิตรอคนจองต่อ (ตัดสินแล้ว):**
- ตรงกับช่วงเวลา/คอร์ทที่ปล่อย ถ้ามีคนจองได้เพียงบางชั่วโมง ให้เครดิตตามจำนวนชั่วโมงนั้น (รายชั่วโมง)
- จำนวนเครดิต = ยอดที่ผู้จองเดิมชำระของชั่วโมงนั้น (ตัดสินแล้ว) ไม่ผูกกับยอดที่ผู้จองใหม่จ่าย
- ออกเครดิตเมื่อสนามกด "จ่ายแล้ว" ให้การจองใหม่ (ไม่ใช่ตอนจองเฉย ๆ) กันกรณีผู้จองใหม่ยกเลิกหรือไม่มา
- การจองที่ใช้เครดิตจ่าย ถ้ายกเลิก เครดิตส่วนนั้นหายไป ไม่ออกเครดิตใหม่จากส่วนนั้นแม้มีคนจองต่อ
- วันหมดอายุนับจากวันที่ออกเครดิต
- ผู้จองเดิมจองช่วงเดียวกันกลับคืนเองไม่นับเป็น "มีคนจองต่อ"

ข้อความนโยบายในหน้า (ตัวอย่าง):
- ≥24 ชม. + ชำระแล้ว: "ยกเลิกได้ถึง พฤ. 29 ต.ค. 18:00 เพื่อรับเครดิต ฿400 ใช้จองใหม่ภายใน 30 วัน"
- <24 ชม. + ชำระแล้ว: "เลยเวลารับเครดิตทันทีแล้ว ยังยกเลิกได้ ถ้ามีคนจองช่วงนี้ต่อ คุณจะได้เครดิตคืน"
- ยังไม่ชำระ: "ยังไม่ได้ชำระเงิน ยกเลิกได้โดยไม่มีค่าใช้จ่าย"

Modal ยืนยันยกเลิก (ใช้ `Modal` เดิม) ต้องบอกผลก่อนกดยืนยัน:
- มีเครดิตทันที: "ยกเลิกการจองนี้ และรับเครดิต ฿400 (หมดอายุ 28 พ.ย. 2569 ถ้ายกเลิกวันนี้)"
- รอคนจองต่อ: "ยกเลิกการจองนี้ ถ้ามีคนจองช่วงนี้ต่อและชำระแล้ว คุณจะได้เครดิตคืน ถ้าไม่มี จะไม่ได้เครดิต"
- ไม่มีเครดิต (ยังไม่ชำระ): "ยกเลิกการจองนี้" ปุ่ม "ไม่ยกเลิก" เป็นปุ่มหลัก ปุ่มยืนยันเป็น `danger`
- หลังยกเลิก: toast "ยกเลิกแล้ว" + (ถ้ามี) "ได้เครดิต ฿400" และหน้าเปลี่ยนเป็นสถานะยกเลิกในที่เดิม ไม่เด้งออก

### 6.3 การใช้เครดิต (อยู่นอกหน้านี้ แต่หน้านี้ต้องไม่ขัด)
- หน้า review (`/book/review`) แสดงยอดเครดิตคงเหลือและให้เลือกใช้ ระบบหักตามลำดับหมดอายุก่อน
- เครดิตไม่คืนเป็นเงินสด ไม่โอนข้ามผู้ใช้
- หน้านี้แสดง "เครดิตที่ใช้" เป็นบรรทัดลบในค่าใช้จ่าย ถ้าการจองนี้ใช้เครดิต
- **ยกเลิกการจองที่จ่ายด้วยเครดิต = เสียเครดิตส่วนนั้นเลย** Modal ยืนยันต้องบอกก่อนกด เช่น "คุณใช้เครดิต ฿400 กับการจองนี้ ถ้ายกเลิกจะไม่ได้เครดิตคืน" และปุ่ม "ไม่ยกเลิก" เป็นปุ่มหลัก
- ถ้าจ่ายผสม (เครดิต + เงินสด) ส่วนเงินสดตามกติกาข้อ 6.2 ปกติ ส่วนเครดิตเสีย (ตีความ ตรวจสอบกับผู้ก่อตั้ง)

## 8. ขอบเขตกรณีพิเศษ

- **เวลาใกล้ตัดสิทธิ์เครดิต:** คำนวณจากนาฬิกาเซิร์ฟเวอร์และ `timezone` ของสนาม ไม่ใช้เวลาเครื่องผู้ใช้ ถ้าผู้ใช้เปิด Modal ค้างไว้จนเลยเส้น 24 ชม. ตอนกดยืนยันเซิร์ฟเวอร์ต้องตอบผลจริงและหน้าแสดง "ตอนนี้เลยเวลาแล้ว จะไม่ได้เครดิต" ให้ยืนยันอีกครั้ง
- **สนามยกเลิกฝั่งสนาม (บล็อกคอร์ท):** สถานะ `cancelled` พร้อมเหตุผล และได้เครดิตเต็มจำนวนทันทีโดยไม่ดูเส้น 24 ชม. (ตัดสินแล้ว)
- **no-show:** ไม่มีสถานะแยกในหน้านี้ใน v1 เจ้าของกด "ไม่มา" ใน owner console แล้วการจองแสดงเป็น "เล่นเสร็จแล้ว/ไม่มาตามนัด" ไม่ออกเครดิต (ตัดสินแล้ว; ข้อความที่แสดงยังต้องกำหนด)
- **หลายคอร์ทในการจองเดียว:** `courtIds` เป็น array แสดงทุกคอร์ท ถ้ามากกว่า 1 ให้ขึ้นเป็นรายการ
- **เครดิตหมดอายุ:** แสดงวันหมดอายุเสมอที่จุดที่เครดิตถูกออก (ในหน้านี้และ LINE ยืนยัน)
- **ภาษา/วันที่:** ใช้ `lib/thai-date.ts` ปี พ.ศ. ตามที่โปรเจกต์ใช้อยู่แล้ว ตัวเลขเงินและเวลาใช้ `tabular-nums`

## 9. การเข้าถึงและเลย์เอาต์ (ตาม DESIGN.md)

- เนื้อหาอยู่ใน `.liff-column` ความกว้างไม่เกิน 430px ปุ่มสูงอย่างน้อย 44px ปุ่มล่างอยู่ในกระแสหน้า ไม่ fixed (กันชนกับ bottom nav)

## 11. เกณฑ์ตรวจรับ

1. กดการ์ดใน `/bookings` เข้า `/bookings/:ref` ได้ ย้อนกลับถูกที่
2. แต่ละสถานะในข้อ 4 แสดงป้ายและข้อความถูกต้อง (มีเทสต์ต่อสถานะ)
3. ยกเลิกที่ 25 ชม. ก่อนเริ่ม + ชำระแล้ว → ได้เครดิตเท่ายอดชำระ หมดอายุ 30 วัน
4. ยกเลิกที่ 23 ชม. → ไม่ได้เครดิต และ Modal บอกก่อนกดยืนยัน
5. ยกเลิกยังไม่ชำระ → ไม่มีเครดิต
6. กดยืนยันยกเลิกซ้ำ ไม่ออกเครดิตซ้ำ
7. การจองของผู้ใช้อื่น/ref ที่ไม่มี → หน้า "ไม่พบ" แบบเดียวกัน
8. ผ่านเทสต์ a11y เดิม (`a11y.test.tsx`) และ `features.test.ts`
9. ไม่มีปุ่มที่กดแล้วไม่เกิดอะไร

## 12. ตัดสินแล้ว และคำถามที่ยังเปิด

ตัดสินแล้ว (2026-10-29): ยกเลิกที่ยังไม่ชำระไม่มีเครดิต · ยกเลิก <24 ชม. ได้เครดิตเมื่อมีคนจองต่อ · สนามยกเลิกได้เครดิตเต็ม · no-show เสียสิทธิ์ · จองด้วยเครดิตแล้วยกเลิก = เสียเครดิต · เครดิตเฉพาะสนามที่ออกให้ (ผู้ใช้แยกต่อสนาม)

| # | คำถาม | ข้อเสนอ |

| 1 | ข้อความ no-show ที่แสดงในหน้า | ยังไม่เห็นภาพ ใช้ข้อความชั่วคราว "ไม่ได้มาตามนัด" แล้วปรับเมื่อทำหน้าจริง |

- ตารางเครดิต (ledger), `PendingCredit` และการจับคู่คนจองต่อ: เดโมบันทึกผลไว้ที่ `Booking.creditOutcome` เท่านั้น จึง**ยังไม่มียอดเครดิตให้ใช้จองใหม่** และหน้า review ยังไม่มีช่องใช้เครดิต
