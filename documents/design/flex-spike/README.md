# Flex spike: ทดสอบก่อนประมาณการ (D64)

ไฟล์ [booking-confirmation.json](booking-confirmation.json) เป็นบับเบิล "ยืนยันการจอง" 1 แบบ ออกแบบให้ทดสอบสิ่งที่ยังยืนยันไม่ได้จากเอกสาร LINE

## วิธีทดสอบ (ทำเองเพราะต้องล็อกอิน LINE)
1. เปิด Flex Message Simulator ใน LINE Developers Console (ต้องล็อกอินบัญชี LINE Developers)
2. เลือก Showcase / New แล้ววาง JSON ใน Bubble
3. ดูผลทั้งในตัวจำลอง และถ้าทำได้ ส่งเข้า LINE จริงเพื่อดูบนมือถือ (ผลต่างกันตามอุปกรณ์/เวอร์ชัน LINE)
4. เปลี่ยน URL รูป hero (ตอนนี้เป็น placeholder) เป็นรูปแบรนด์จริงผ่าน HTTPS (JPEG/PNG)

## เช็กลิสต์ผล (กรอกหลังทดสอบ)
| สิ่งที่ทดสอบ | อยู่ในไฟล์ตรงไหน | ผล (ได้/ไม่ได้/เพี้ยน) |
|---|---|---|
| พื้นหลังไล่สี (`linearGradient`) | กล่องหัวสีน้ำเงิน | |
| มุมโค้ง `cornerRadius` | กล่องหัว, กล่องเลขอ้างอิง | |
| ขอบ `borderWidth` | กล่องเลขอ้างอิง | |
| ฟอนต์ไทย ตัดบรรทัด `wrap` | บรรทัด "คอร์ท 3 · พรุ่งนี้ …" | |
| ป้ายปุ่มยาว (ปุ่มที่สอง) ถูกตัดไหม | ปุ่ม "เปิดดูกระดานคะแนนสด…" | |
| รูป hero ผ่าน HTTPS | `hero` | |
| ความสูงรวม ขนาด `mega` พอดีไหม | ทั้งบับเบิล | |

## ยังไม่ได้ทดสอบ (เพิ่มได้ถ้าต้องการ)
- เงา (shadow), position absolute + offset, ไอคอน, ขนาดบับเบิลอื่น
- ขนาด JSON สูงสุด, จำนวนบับเบิลใน carousel (ดูใน Messaging API reference)

## หลังทดสอบ
บันทึกผลในตารางด้านบน แล้วอัปเดต D64 ใน `../../audit/register.md` ให้ตรงกับผลจริง และทำ v1 Flex ที่ต้องใช้ (ยืนยันการจอง, เตือน 30 นาที, ยกเลิก/คืนเครดิต) ตามผลนั้น

หมายเหตุ: ปุ่มที่สองตั้งใจใช้ป้ายยาวจาก mockup เดิม เพื่อดูว่าถูกตัดจริงหรือไม่ (ไม่ใช่ปุ่มที่จะใช้จริงใน v1)
